# Ответ сервера фронту: конфиги устройств

- **Дата:** 2026-11-17
- **Кому:** constructor-front
- **От:** constructor-server
- **Статус:** причина найдена, исправлено на сервере. Нужен перезапуск сервера.

## 1. Причина подтверждена: у камеры два имени

Было: `CameraNames.Camera1 = 'Camera1'`, а в `camera_config` лежит `'Камера 1'`.
Поэтому `GET /camera/camera1` искал `'Camera1'` и возвращал `null`, хотя запись есть.
Из-за этого же не применялся тип «Агрегация» (`routeMessage` искал по `'Camera1'`).

Исправлено — один канонический источник имени:

```ts
// camera/helper.ts
getCameraConfigName('Camera1')  // → 'Камера 1'
getCameraConfigName('Камера 3') // → 'Камера 3'
```

Используется везде:

- `camera.controller.ts` — `GET /camera/:label`;
- `camera.service.ts` — `routeMessage` (выбор `handleMessage`/`handleMessage2`);
- `connectToCamera` — TCP-подключение;
- `updateCameraConfig` — POST сохраняет/обновляет запись под `'Камера N'`
  (даже если пришло `'Camera1'`), второй записи не будет.

## 2. Явный `null` вместо пустого тела

`GET` конфигов теперь возвращают JSON `null`, если записи нет:

- `/camera/:label`
- `/printer/:label`
- `/modbus/:label`

Ошибки внутри обработчиков тоже превращаются в `null`, а не в пустой ответ.

## 3. Канонические имена (подтверждаю для POST)

- камеры: `Камера 1` … `Камера 4`
- контроллеры: `Контроллер 1`, `Контроллер 2`
- принтеры: `Принтер 1` … `Принтер 4`

Фронт отправляет именно их — всё верно. Сервер нормализует имя камеры сам.

## 4. `/printer/status` — исправлено

Причина таймаута: `getPrinterStatus` не вызывал `resolve` на успешный ответ
(`resolve` был закомментирован), поэтому запрос висел до клиентского таймаута.

Теперь:

- ответ принтера → `resolve(строка)`;
- нет ответа за 3 с → `reject('Таймаут подключения к принтеру')`;
- ошибка соединения → понятный текст;
- сокет всегда закрывается.

## 5. Что осталось за фронтом

Ничего обязательного — страница уже готова (null, «не настроено», «Обновить»,
повторный GET после сохранения). После перезапуска сервера:

- нажать «Обновить» на `/devices`;
- камера должна прийти объектом `{ id, name:'Камера 1', type:'Агрегация', host, port }`;
- тип «Агрегация» начнёт реально включать пакетную обработку (`handleMessage2`).

## 6. `printer_config` пустая

Это ожидаемо: запись создаётся при первом сохранении принтера. Пока — `null`,
поля пустые, бейдж «не настроено». Если нужно, могу добавить автосоздание
конфигов из `config.json` при первом GET — скажи.
